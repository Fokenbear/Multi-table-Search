# Excel 解析模块说明

本文件是解析模块的说明文档，设计说明、兼容性说明和测试记录合并在本文件。

状态：已实现并通过合成测试与真实样本测试。真实业务样本不进入仓库。

## 1. 入口与接口

```python
from app.contracts import ParsedWorkbook
from app.excel_parser import WorkbookParser

workbook: ParsedWorkbook = WorkbookParser().parse_workbook(
    r"C:\path\to\sample.xlsx"
)
```

- `WorkbookParser()` 无必需构造参数，构造与模块导入没有文件扫描、UI、网络或 COM。
- 唯一公开入口 `parse_workbook(path: str) -> ParsedWorkbook`，
  与 `app/contracts.py`（`INTERFACE_VERSION = "2.0"`）一致。解析器不知道工作簿在索引里的编号，
  编号由 `DataManager` 在写入时分配。
- 同步执行；不依赖 Qt、SQLite、WPS、搜索服务或数据库。
- 只读输入文件；返回不可变 DTO，集合均为 tuple。
- 预期失败抛 `ContractError`：路径/格式参数错误、文件不存在/不可读、ZIP 或
  OOXML 损坏、解析失败。不会用“空工作簿成功”掩盖解析失败。

实现文件：

| 文件 | 职责 |
| --- | --- |
| `app/excel_parser/parser.py` | 入口、输入校验、有效范围/区域/表头/列识别、合并传播、DTO 组装 |
| `app/excel_parser/ooxml.py` | ZIP/关系解析、空 fill 修复、临时副本、公式 XML 扫描 |
| `app/excel_parser/values.py` | 原始值分类、显示值格式化（日期、数字、前导零、百分比、文本、布尔、错误） |
| `app/excel_parser/__init__.py` | 导出 `WorkbookParser` |

## 2. OOXML 兼容性修复

真实文件 `xl/styles.xml` 的 `<fills>` 中存在 3 个空的 `<fill/>` 或 `<fill></fill>`
节点，openpyxl 3.1.5 会抛出 `TypeError: expected Fill`。

处理方式：

1. 直接读取 ZIP 的 `xl/styles.xml`，用正则只检查 `<fills>` 块内的空 fill，决定是否修复。
2. 需要修复时，把工作簿逐项复制到 `tempfile.mkstemp()` 创建的临时 `.xlsx`；
   只有 `xl/styles.xml` 被改写，其余部件逐字节不变。
3. 空 fill 语义上等于默认“无填充”，改写为
   `<fill><patternFill patternType="none"/></fill>`；字体、边框、数字格式、
   共享字符串、公式、合并区域和所有工作表数据均保留。
4. 用 openpyxl 从临时副本读取；解析结束（包括异常）后删除临时文件。
5. 原始文件只以只读方式打开；测试在解析前后计算 SHA-256 并断言相同。
6. 不需要修复的文件直接读取原始路径，不复制。
7. 如果修复后仍不能读取，抛 `ContractError(ErrorCode.PARSE_FAILED)`，不会尝试跳过样式
   或丢弃数据。

不要求安装 LibreOffice，不修改原始 Excel，不执行宏。

## 3. 解析规则

### 3.1 有效范围

- 只把有原始值、公式或合并锚点值的单元格视为有效内容，不使用 `max_row` /
  `max_column`。真实样本中样式虚增到 12966 行、189 列，而实际有效范围是
  1238 行、22 列；解析器按实际内容工作。
- 隐藏行、隐藏列完整参与解析，不跳过。
- 完全空白的工作表返回 `tables=()`，并给 `EMPTY_SHEET` 警告。

### 3.2 数据区域

- 以有效内容行构造区域。两个有效内容行之间至少相隔 2 个完全空白行时，拆成独立区域。
  单个空白行保留在同一表格内并跳过该空行。
- 每个区域独立识别标题、表头、数据起始行和有效列。
- 同一 Sheet 的多个纵向区域分别生成 `ParsedTable`，`table_index` 在同 Sheet 内从 1
  连续编号，按起始行、起始列排序。
- 同一行带的并排区域：当两个表头簇之间存在整列为空的间隔时，拆成两个
  `ParsedTable`，同一 Excel 行可分别出现在两个表的 `rows` 中（与架构文档一致）。
  右侧无表头备注不会被拆成独立表格，而是归入最后一个表头块。

### 3.3 表头与标题

不使用“第一行必为表头”的假设。识别顺序：

1. 跳过区域开头的空行。
2. 如果第一行只有一个短文本标签，且下一行是表头样行，则第一行是标题；
   否则如果第一行是表头样行，则它是表头。
3. 表头样行：所有非空值都是字符串、无换行、长度不超过 40，且至少包含两个已识别字段标签（单列时一个）。
   单个稀疏表头（例如只有 `H1=供应商`，左侧列无表头）也允许。
4. 第二行是表头、表头前有标题、表头前有空行均已覆盖。
5. 多行表头只在“上一表头行包含横向合并标签”且下一行仍是表头样行时合并；
   每个原始片段用换行符连接，`header_rows` 保存全部原始行号。
6. 标题存在时优先用标题文本作为 `table_name`；否则使用 Sheet 名。原始表头文本不
   trim、不改写、不拆分。
7. 不能可靠识别表头时：
   - `header_rows=()`，所有列 `header=None`；
   - 保留全部数据；
   - 增加 `HEADER_NOT_FOUND` 警告；
   - 不静默跳过 Sheet。

### 3.4 有效列、重复表头、补充备注

- 有效列为“表头列 + 数据列 + 数据区合并锚点列”的并集；完全空且无表头的列不输出。
- 有表头但当前行为空的列仍输出空白 `ParsedCell`。
- 重复表头全部保留：例如 H/I/J 三列都保持 `header="供应商"`，不合并、不去重。
  展示层的 `（H列）` 后缀由格式器负责，解析器不改 `header`。
- 无表头列：
  - 位于最后一个表头列左侧：`header=None, is_supplementary=False`；
  - 位于最后一个表头列右侧：`header=None, is_supplementary=True`；
  - 整个表没有表头：全部 `is_supplementary=False`。
- 数据行包含该区域全部有效列；空白字段是
  `raw_value=None, display_value="", data_type="blank"`，数值 0 和 `False` 不是空白。

### 3.5 合并单元格

- 纵向合并：覆盖的每个数据行生成该行逻辑坐标的单元格，值取左上角；
  非锚点行 `origin_address` 为锚点地址，锚点行 `origin_address=None`。
- 横向合并：只在左上列生成一个逻辑值，覆盖的其他列不重复报价文本。
- 二维合并：只在锚点列纵向传播，其他列不重复。
- `address` 始终是逻辑行坐标（如 `A3`），打开 WPS 时使用该逻辑地址；
- `ParsedTable.merged_ranges` 保存与表格范围相交的原始合并范围，如 `A2:A14`。
- 同一列同一行最多一个单元格，不重复输出同一地址。
- 超过 20000 行的超大合并明确报验证失败，拒绝不完整导入并保留旧数据，不再截断。

### 3.6 公式与缓存值

- 通过 `zipfile` + `ElementTree.iterparse` 直接读工作表 XML，收集 `<f>` 公式原文和
  `<v>` 缓存值。
- `raw_value` 保留 `=...` 公式原文，`data_type="formula"`。
- 有缓存：`display_value` 为按数字格式格式化的缓存结果，
  `formula_has_cached_value=True`。
- 无缓存（包括 openpyxl 写出的空 `<v/>`）：`display_value` 为公式原文，
  `formula_has_cached_value=False`，并产生 `FORMULA_WITHOUT_CACHED_VALUE` 警告。
- 不计算、不猜测公式结果；不执行宏。
- 共享公式从属单元格按主公式原坐标展开相对引用，保留绝对引用，不计算结果；
  有缓存值时以缓存结果为准。
- 真实样本没有公式单元格；合成测试覆盖了有缓存和无缓存两种情况。

### 3.7 显示值

`RawValue` 保留 Python 标量类型；`display_value` 尽量复现 Excel 显示：

- 文本：原样保留（首尾空格、制表符、换行、连字符、特殊字符均不改）。
- 日期/时间：识别 `yyyy/mm/dd`、`m"月"d"日"`、`m/d`、`hh:mm:ss` 等常见格式；
  真实样本的 `m"月"d"日";@` 输出如 `5月14日`。
- 数字：支持 `General`、`0`、`0.00`、`#,##0.00`、`0.0000_ `、`0_);[Red](0)`、
  百分比、货币前缀、前导零格式（`000000` → `000007`）等。
- `date`/`datetime`/`time`/`duration` 原值保留类型；仅 `str()` 不足以表达类型，
  数据库序列化由存储层按接口约定处理。
- `True`/`False` 显示为 `TRUE`/`FALSE`；错误值保留 `#N/A` 等文本。
- 无法完整复现的数字格式回退为 `General`，并产生 `DISPLAY_FORMAT_FALLBACK`
  警告（带首个单元格地址和计数），不静默丢弃数字格式。
- 搜索层应使用 `display_value` 做 `strip().casefold()` 后的单元格级包含匹配；
  解析器不拼接单元格。

## 7. 性能

样本：21,348,026 字节，28 Sheet，压缩后约 10.5 MB XML 数据。

| 指标 | 结果 |
| --- | --- |
| 正常解析（含样式修复临时副本、公式扫描、全部 DTO 构造） | 2.16 s |
| 峰值工作集（正常解析） | 152.4 MB |
| `tracemalloc` Python 分配峰值 | 113.3 MB |
| 解析结果 | 27 个表，3166 条数据行 |

说明：开启 `tracemalloc` 后解析约 9.3 s，这是插桩开销，不是生产耗时。
解析器只遍历 openpyxl 已存在的单元格（真实文件约 24.9 万个样式单元格、6743 个有值单元格），
不遍历 12966×189 的虚增矩形。

搜索性能不在本模块范围；解析结果按单元格保留 `display_value`，供搜索层逐格匹配。

## 9. 已知限制与风险

1. 只支持 `.xlsx`；`.xls`、`.xlsm`、`.csv` 明确报 `UNSUPPORTED_FORMAT`，
   不做静默转换，也不执行宏。
2. 表头识别是启发式：
   - 全字符串短行只有匹配足够明确字段标签才作为表头；未知短文本仍作数据保留；
   - 单行表头若带数字/日期（例如年份表头）会被当作数据而降级为无表头；
   - 多行表头只在有横向合并标签时合并。
   这些情况都会保留全部数据并给 `HEADER_NOT_FOUND`，不会丢行，但字段标签可能不理想。
3. 纵向区域以“≥2 个连续空行”分隔；只隔 1 个空行会被视为同一表格。并排区域以
   “表头簇之间整列为空”分隔；如果右侧备注与数据之间隔了空列，备注仍归入最后表头块。
4. 超过 20000 行的合并范围明确拒绝导入，不能输出截断的成功结果。
5. 共享公式相对引用已正确展开；无法展开时明确失败，有缓存值时以缓存显示结果为准。
6. 复杂数字格式（条件格式、科学计数、多条件区段）会回退为 `General` 并给警告；
   不保证像素级复现 Excel/WPS 的本地化显示。
7. 未实现图表 Sheet 的数据解析（工作簿只有 worksheet；图表没有单元格数据）。
8. `openpyxl` 的 `_cells` 是内部属性；已固定 `openpyxl==3.1.5`。升级 openpyxl 需要重新
   运行本模块测试和真实样本测试。
9. 真实样本只在本机验证，未在目标使用者的 Windows 10 + WPS 环境重复验证；本模块不涉及
   WPS 自动化。
10. 解析器不校验“不同工作簿是否使用同一模板”，也不处理业务去重；这些属于 DataManager/
    SearchService。解析器保留同一料号在不同 Sheet/行的全部记录。
